An HTTP 500, an HTTP 000, a different status or a lost marker is reported as **ROLLBACK FAILED OR UNVERIFIED (exit 3)** with the manual steps and the backup path; verified recovery exits 1. After the point of no return an `ERR` trap sends ANY failing command (for example the removal of the live files) into the rollback, so the script cannot exit with the UI down and no recovery attempt. HTTP 200 alone is no longer accepted.
