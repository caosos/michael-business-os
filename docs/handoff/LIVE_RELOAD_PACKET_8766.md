## Script safety (A-54, ARYA-0718): tested in isolation, never against :8766
`tools/reload_ui.sh` now runs `set -euo pipefail` and aborts BEFORE stopping anything or removing any live file unless ALL prerequisites pass: the commit is on lane 06's pushed branch; the export succeeded and contains `operator_ui/{server,market_view,market_search}.py` and `comms_spec`; the live UI directory is complete; the backup copy succeeded, `diff -r` against live is clean and the file counts match. It writes `ARTIFACT` (`sha=` and a sha256 tree hash of `operator_ui` + `comms_spec`) into the live directory, and after the restart proves identity AND behaviour: the files on disk hash to the artifact; the `mbos-dev-ui` session exists; `GET /` is a 303 to `/market`; `/market` contains the Save-form fields (`cat`, `row1`, `row4`, `condition`, `any`) and "Gallery rows"; a negative radius shows `filter-errors`; `/mission` and `/queue` show no fictional content. Any failure restores the verified backup and restarts the old UI. **Rollback is judged against a baseline** read (GET only) from the UI that is serving before the change: recovery is accepted only if `/market` gives the same healthy answer as at baseline (HTTP 200, and the marketplace marker if the old page had it). An HTTP 500, an HTTP 000, a different status or a lost marker is reported as **ROLLBACK FAILED OR UNVERIFIED (exit 3)** with the manual steps and the backup path; verified recovery exits 1. After the point of no return an `ERR` trap sends ANY failing command (for example the removal of the live files) into the rollback, so the script cannot exit with the UI down and no recovery attempt. HTTP 200 alone is no longer accepted.
