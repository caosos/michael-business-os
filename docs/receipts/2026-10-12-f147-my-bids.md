# F-147: "I bid on this" + My bids window on /market (implements A-61)

Provenance: queue row F-147 (owner P0, in chat 2026-10-12: watch the bids I have in, and do not show them in my search lineup); A-61 rules reused; F-146 `6c2ac71`.

What changed (DRY-RUN, no external call, no credential, no spend):
- `operator_ui/market_bids.py` (new): mark / unmark / set-max, exclusion helper, the window, the card control.
- Record path: the existing owner-local market prefs store (`operator_ui/market_prefs.py`, file `var/market_prefs.json` or `MBOS_MARKET_PREFS_FILE`), new key `bids`, separate from `hidden` and `saved`. No new datastore. D-33 watchlist storage was not used because /market already persists its owner choices in this file. `reset` now keeps `bids`.
- `POST /market/bid` (CSRF only; nothing is placed, fetched or sent). Every card variant (GSA gallery/list, Wooley event, alert-source, owner find) gets the control through `pref_buttons`.
- Window: top of the sidebar (stacks above filters on mobile), closing-soonest first, title, source, countdown, current bid and bid count (UNKNOWN when the source gives none, e.g. Wooley events), as-of time, original link, Stop tracking, optional max bid. Shown under any filter, radius or source. Live source values replace the marking-time snapshot when the loaded source has the item.
- Tracked items are excluded from results (GSA, unchecked, finds) with a visible "N in My bids" count; stop tracking returns them.
- Owner-reported only: Save never marks a bid (tested). Max bid stays in the local prefs file (`var/` is not committed), shown only in the window.

Tests: `tests/test_market_f147.py` (6): control and Save independence, exclusion + count + un-track, persistence and any-filter window, UNKNOWN fields / escaping / bad max, ordering and reset, CSRF. Full health result is in AGENT_STATUS.
Not done: Chrome desktop+mobile screenshots (Agent 01 verifies); no countdown ticking client-side (computed at page load).
