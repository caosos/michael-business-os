## Rule implemented
For each failed gate (or the composite floor, when no gate failed), the PASS is evidence-backed under that gate's rule. **The PASS archives only if at least one failed gate is evidence-backed.** Otherwise `pass_on_priors = true`, and the item stays in RESEARCHING (A-12).

| Gate kind | Rule |
|---|---|
| Flip economic gates (`ev_positive`, `pph_floor_ok`, `min_profit_ok`, `distance_ratio_ok`, composite floor) | **revenue side** (`resale.target_sell_price`) **AND ≥ 1 cost-side input** (expected buy price, buy fees, parts, materials, labor hours, admin hours) evidence-backed |
| Flip `cash_ok`, `max_loss_ok`, skill/license | ≥ 1 decisive input evidence-backed. Revenue is not an input to these gates |
| All service gates | ≥ 1 decisive input (unchanged, per the amended ruling) |

**Evidence-backed** means an `estimates_meta.assumptions[]` record with basis FACT, or one marked `evidence_backed` by the estimator (the comp median from FACT sold comps).

## Correction to my own C-05 design (INFERENCE → fixed)
C-05 listed `acquisition.ask_price` as a decisive input. It is not one: no formula reads the ask. It is *evidence for* `expected_buy_price` (= ask × negotiation factor, a REC prior). Counting it was the loophole P-03-04 described. **Decisive inputs are now arithmetic inputs only.** A test asserts that the ask never appears among decisive inputs.
